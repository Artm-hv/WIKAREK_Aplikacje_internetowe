## Lab 1 — Apache

Вимоги та перевірені вихідні файли: [^https://github.com/Artm-hv/WIKAREK_Aplikacje_internetowe/blob/11071d0f0e01ae38bcf8c7045b9aa859790f48a8/02-Laboratorium/pti_01-konfiguracja_apache.pdf][^https://github.com/Artm-hv/WIKAREK_Aplikacje_internetowe/blob/11071d0f0e01ae38bcf8c7045b9aa859790f48a8/04-Gotowe_Laborki/Lab_01/httpd_append.conf][^https://github.com/Artm-hv/WIKAREK_Aplikacje_internetowe/blob/11071d0f0e01ae38bcf8c7045b9aa859790f48a8/04-Gotowe_Laborki/Lab_01/INSTRUKCJA_KROK_PO_KROKU.md]

### Підтверджено

За `httpd_append.conf` реалізовано DocumentRoot, слухання 8080 і 443 з припущенням наявного Listen 80, стартові файли, п'ять HTTP-віртуальних хостів і SSL-хост, ServerAlias, autoindex, HeaderName/ReadmeName, власні помилки, Basic Auth, обмеження phpMyAdmin за IP, `/status`, TLS та логування.

У локальній адаптації перевірено:

Хеш у `hasla.has` відповідає паролю `st`. Папка `historia` вже відстежується через `.gitkeep`; `meble/error/403.html` уже є. Старі зауваження про їхню відсутність більше не актуальні.

### Що доробити

1. **Повний конфіг та запуск на ВМ.** Є лише фрагмент `httpd_append.conf`, а PDF вимагає додати до звіту `httpd.conf`. Після інтеграції необхідно зберегти саме повний робочий конфіг. Наявні директиви Listen, модулі, інші vhost і SSL-файли можуть впливати на запуск; мінімальна Linux-перевірка не доводить запуску повного Windows-конфігу.
2. **Інструкція restart недостатньо точна.** Після `httpd -t -f D:\cw_01\httpd.conf` наведено просто `httpd -k restart`. Треба переконатися, що ярлик/служба використовує саме змінений конфіг; інакше перевірений та запущений конфіги можуть відрізнятися. Якщо `httpd`/`openssl` не в PATH — потрібні повні шляхи до виконуваних файлів.
3. **Не вгадувати місце phpMyAdmin.** У фрагменті жорстко задано `C:/Oprogramowanie/Apache24/htdocs/phpMyAdmin`. На ВМ слід звірити фактичний наявний каталог, не створювати його заново і не змінювати заборонений системний каталог.
4. **Точна дата підвала.** `meble80/stopka.html` містить лише `2026 r.`, а потрібно вказати дату виконання.
5. **Захист файлу паролів — додаткова безпекова рекомендація.** `hasla.has` лежить під основним DocumentRoot без окремої HTTP-заборони. У локальному тесті через адресу, що потрапляє в основний сервер, файл повернувся з HTTP 200. Варто винести його поза публічний каталог або явно заборонити доступ. Це не тотожне порушенню окремого пункту оцінювання, але реальний ризик конфігурації.
6. Додати в інструкцію перевірку alias без `www`, phpMyAdmin, рівнів обробки 403/404 та вмісту полів сертифіката. У послідовності команд і BAT відрізняється запис Locality з номерами альбомів — уніфікувати.

## Lab 2 — HTTP, SMTP, POP3, FTP

Вимоги та перевірені вихідні файли: [^https://github.com/Artm-hv/WIKAREK_Aplikacje_internetowe/blob/11071d0f0e01ae38bcf8c7045b9aa859790f48a8/02-Laboratorium/pti_02-protokoly.pdf][^https://github.com/Artm-hv/WIKAREK_Aplikacje_internetowe/blob/11071d0f0e01ae38bcf8c7045b9aa859790f48a8/04-Gotowe_Laborki/Lab_02/PUTTY_COMMANDS_CHEAT_SHEET.txt][^https://github.com/Artm-hv/WIKAREK_Aplikacje_internetowe/blob/11071d0f0e01ae38bcf8c7045b9aa859790f48a8/04-Gotowe_Laborki/Lab_02/auto_ftp.bat]

### Що готово

Команди покривають основні завдання: GET/HEAD, Basic Auth, чотири поштові сценарії, POP3 STAT/LIST/TOP/RETR неіснуючого повідомлення/DELE, FTP PASV/LIST/RETR/MKD/STOR та Windows ftp.exe. Base64 для `wykladowca:wykladowca` правильний.

### Що не можна вважати виконаним

`http.txt`, `poczta.txt`, `ftp1.txt`, `ftp2.txt` — заготовки/зразки. Це прямо визнає DOCX. Зокрема, `GIF89a...[dane binarne grafiki GIF]...` не є справжнім отриманим зображенням. Необхідно виконати команди в мережі ВМ і зберегти реальні відповіді, а не подавати очікувані як результати.

### Недоліки інструкції

- Для HTTP/1.1 на 8080 використовувати `Host: www.student.pl:8080`; у TXT-шпаргалці порт у Host відсутній.
- Для FTP детально описати життєвий цикл каналу даних: новий PASV, обчислення порту, окреме з'єднання, LIST/RETR/STOR, завершення передачі даних (EOF/закриття каналу), очікування 226. Для каналу даних доцільний Raw, щоб Telnet-переговори не змінювали дані. Нинішня шпаргалка не пояснює завершення STOR.
- `auto_ftp.bat` використовує відносні шляхи без `cd /d "%~dp0"`; запуск із чужого поточного каталогу може не знайти `ftp_commands.txt` та файли для надсилання.
- Немає окремої цілісної інструкції: створення каталогу, збереження логів, порядок тестів, вивантаження та ZIP.
- DOCX містить інші приклади акаунтів (`student`, адреси `@student.tu.kielce.pl`), ніж методичка та TXT (`student1`, `@poczta.student.pl`); синхронізувати.
- PDF сам суперечливий щодо `ftp.txt`/`ftp1.txt` і назви архіву. Це не доведена помилка студента. Уточнити в викладача або додати сумісну копію `ftp.txt`.

### КРИТИЧНО: звичайна форма не проходить валідацію

`a1.php`, рядки 147–149:

```php
$allowed_typ = ['stacjonarnie', 'zdalnie'];
```

Той самий файл, рядки 392–393:

```html
<option value="Stacjonarnie">Stacjonarnie</option>
<option value="Zdalne">Zdalne</option>
```

Жодна опція браузера не відповідає білій таблиці PHP. В обох перевірених браузерних сценаріях з іншими коректними даними повертається `*Wybierz opcje`, кнопок підтвердження немає.

**Виправлення:** встановити узгоджені `value="stacjonarnie"` та `value="zdalnie"` і відповідні порівняння для збереження вибраної опції. Текст підписів можна залишити читабельним.

### Що вже працює

Прямими HTTP-запитами з правильними серверними значеннями перевірено: прийняття коректних даних; відхилення порожніх полів, неіснуючої дати, віку <16, невідповідної дати PESEL, надто довгого прізвища, стороннього типу занять і відсутності курсу; підтвердження; створення `z_001.txt`; скасування; відмову від прямого запису без валідованої сесії.

Ці тести доводять працездатність серверних гілок, але НЕ скасовують блокера користувацької форми.

### Інші зауваження

- Файл використовує `mb_strlen`/`mb_strtoupper`; інструкція має зазначати необхідність `mbstring` і права запису в робочу папку.
- Інструкція наказує копіювати тільки `a1.php`, тому `.htaccess` не потрапляє на ВМ. Треба копіювати й його та перевірити, чи Apache дозволяє його застосування.
- `.htaccess` забороняє `licznik.txt`, але реальний лічильник — `licznik_zgloszen.dat`.
- Формат рядка курсів відрізняється від рисунка PDF: нині пробіли замість `;`. Якщо потрібне точне відтворення, використовувати відповідний роздільник. Назва `z_001.txt` відповідає текстовій вимозі, навіть якщо рисунок PDF демонструє іншу назву.
- PDF у валідації згадує «nazwisko i imię», але перелік полів і рисунки мають лише прізвище. Відсутність окремого `imie` не оголошую однозначним дефектом: це неузгодженість методички.
- Контрольна сума PESEL не вказана як обов'язкова вимога — її відсутність не є зафіксованим порушенням.
- У DOCX неправильно названо файл лічильника та заявлено LOCK_EX у `file_put_contents`, якого фактично немає. Лічильник має власне блокування, тому це не доказ дублювання номерів, а розбіжність звіту з кодом.

Оригінальний PDF вимагає виконати тему, призначену викладачем, а НЕ обов'язково всі вісім. Для наявного комплекту перевірено кожну тему.

### Спільні дефекти

1. **Неправильні одиниці строку сесії в усіх інсталяторах.** Форма підписана хвилинами та надсилає 30. Код застосовує `max(300, min(86400, ...))`, записуючи 300 у `SESSION_LIFETIME`. Адмінка далі множить на 60: прикладна перевірка стає 18000 секунд замість очікуваних 1800. Реальна тривалість також залежить від PHP session GC, тому це саме помилка конфігураційної логіки, не гарантія збереження сесії 5 годин.
2. **Некоректна обробка помилкового підключення.** `@new mysqli` не замінює `try/catch`. У стандартному strict-режимі сучасного PHP помилка підключення кидає виняток до перевірки `$conn->connect_error`; задуманий fallback на порожній пароль може не виконатися. Інсталятори не мають відповідного catch. На PHP 8.5 режим strict підтверджений інтроспекцією; конкретний збій з навчальною БД не відтворювався.
3. **Запис конфігу й install.lock не перевіряється.** У разі неможливості запису код усе одно може показати успіх. Необхідні перевірки прав і результатів операцій.
4. **Не всі параметри тем можна налаштувати.** Каталоги новин/фото, якість, формати, ліміти сторінок/час голосування здебільшого зашиті в коді. Для фото керування форматами та якістю окремо вимагається тематичним завданням.
5. **Кілька тем не ізольовані.** Однакова БД, префікс і ключ сесії `admin_auth`. Особливо теми 5 та 6 створюють однаково названу таблицю `zablokowane_ip`, але лише тема 5 вимагає `data_blokady`. Встановлення по черзі з одним префіксом може спричинити помилки запитів. Якщо розгортається лише одна призначена тема, це не обов'язково проявиться. Для спільного демонстраційного стенда потрібні різні тематичні суфікси після обов'язкової частини `T_група_станок_`, окремі каталоги та ізоляція сесій.
6. **Безпекове посилення понад основну функціональність.** У багатьох адмінках зміни даних виконуються GET-запитами без CSRF-токенів. Перевести зміни на POST і додати CSRF-захист. У порталі обмежити локальний include дозволеною директорією, для зовнішніх URL — допустимими схемами. Це не доводить провалу конкретного пункту методички, але потрібно для тверджень про «повну безпеку».

## Lab 6 — XML/DTD/XSLT/SimpleXML

Вимоги та перевірені вихідні файли: [^https://github.com/Artm-hv/WIKAREK_Aplikacje_internetowe/blob/11071d0f0e01ae38bcf8c7045b9aa859790f48a8/02-Laboratorium/pti_06%20XML.pdf][^https://github.com/Artm-hv/WIKAREK_Aplikacje_internetowe/blob/11071d0f0e01ae38bcf8c7045b9aa859790f48a8/04-Gotowe_Laborki/Lab_06/Wariant_A_Klient_Towar/index.php][^https://github.com/Artm-hv/WIKAREK_Aplikacje_internetowe/blob/11071d0f0e01ae38bcf8c7045b9aa859790f48a8/04-Gotowe_Laborki/Lab_06/Wariant_A_Klient_Towar/relacja.xsl][^https://github.com/Artm-hv/WIKAREK_Aplikacje_internetowe/blob/11071d0f0e01ae38bcf8c7045b9aa859790f48a8/04-Gotowe_Laborki/Lab_06/Wariant_I_Samolot_Pasazer/baza.xml][^https://github.com/Artm-hv/WIKAREK_Aplikacje_internetowe/blob/11071d0f0e01ae38bcf8c7045b9aa859790f48a8/04-Gotowe_Laborki/Lab_06/INSTRUKCJA_KROK_PO_KROKU.md]

### Підтверджено для A–I

- Усі 9 `baza.xml` проходять внутрішню DTD-валідацію.
- Ручна/програмна перевірка типів посилань: кожен ref1 веде в перший довідник, ref2 — у другий, а не просто на довільний наявний ID.
- У кожному варіанті 3 записи в кожному довіднику; 4 або 5 зв'язків.
- Обидві XSLT трансформуються: `tabela.xsl` виводить шість довідникових рядків; `relacja.xsl` — потрібні зв'язки з іменами/назвами, не лише ID.
- PHP виводить усі зв'язки, а кожен із трьох фільтрів у кожному варіанті повертає очікувані записи — 27 перевірок фільтрів.

Помилки відносного XPath та відсутнього JOIN зі старого аудиту виправлені.

### Що уточнити

1. **DTD не доводить 3NF.** Для A–H структура окремих сутностей і зв'язку відповідає простій навчальній моделі; потрібно коротко пояснити ключі й залежності у звіті, а не називати ID/IDREF автоматичним доказом нормалізації.
2. **Варіант I має ризик моделювання.** `lot` зберігається в кожному бронюванні разом із посиланням на літак. Якщо конкретний рейс визначає конкретний літак, виникає залежність `id бронювання → рейс → літак`. Для строгої моделі краще окрема сутність рейсу з датою/часом і літаком, а бронювання посилається на рейс. Без визначених предметних залежностей не оголошую це автоматичним провалом 3NF, але через нуль балів за ненормалізовану модель це важливо узгодити.
3. **Не описано застосування `tabela.xsl`.** XML за замовчуванням підключає лише `relacja.xsl`. Відкрити або показати сам XSL — не означає показати результат трансформації. Додати перемикач представлення або інструкцію тимчасової заміни xml-stylesheet в копії XML і перезавантаження; стабільніший варіант — PHP XSLTProcessor з перевіркою розширення xsl.
4. **Не відкривати XML просто як локальний file:// без застережень.** Політики браузерів можуть блокувати XSLT; показувати через `http://st.pl/...`. Підтримка браузерного XSLT залежить від версії, тому мати серверний резервний варіант.
5. PDF вимагає провести валідацію; формулювання пам'ятки «якщо викладач вимагає» некоректне. Пункт виконати обов'язково і зберегти доказ для свого варіанта.
6. У пам'ятці та DOCX показано універсальні `relacje/relacja`, `@ref1_id`, яких у конкретному A немає (`zakupy/zakup`, `@ref1`). Позначити як псевдоприклад або замінити точним фрагментом обраного варіанта.

## Докази та відтворюваність

Супровідний ZIP містить інвентар, JSON із результатами тестів і скрипти тестування. Скрипти запускають лише локальні копії; для повторення потрібні відповідні PHP/Apache/Chromium і Python lxml. Адаптований Apache-конфіг не є конфігом для здачі на Windows.

Результати успішних HTTP-запитів Lab 4 з серверними значеннями треба читати РАЗОМ із `test_lab4_ui.json`, де обидві реальні опції форми відхилені. Ця різниця навмисно збережена: тестування лише backend без UI дало б помилковий висновок про готовність.
